# Consistency Test Results

## What is tested

The consistency test loads a **test harness page** (`tests/harness/`) that bundles the **real `src/core/detection.ts` and `src/core/calibration.ts`** via Vite. The harness exposes `window.plumbline.run()` which runs `detectCharucoCorners()` and `calibrate()` from real source code. `CORE_VERSION` is asserted to prove the real code is running.

## Synthetic Image Renderer

Images are generated by `tools/reference/render_inverse.py` using **inverse mapping**: for each output pixel, undistort to get a camera ray, intersect the board plane (transformed by R,t), sample from the board texture. This correctly handles lens distortion, unlike the earlier warp-perspective renderer.

Render accuracy verified by `tools/reference/verify_render.py`: projected truth corners vs. detected corners average < 0.9 px (the ~0.5 px floor is sub-pixel detection bias from the ksize=3 Gaussian blur applied during rendering).

## Low Corner Count Diagnosis

Some good-dataset images detect only 9–12 of 24 charuco corners. Root cause: **the board extends partly beyond the image edges** when placed near corners/edges at large apparent size (12–35% area). Markers on the off-screen portion are not detected, and `minMarkers=2` filters charuco corners that border only one detected marker. With `minMarkers=1`, these images detect 15–17 corners. This is expected behavior for boards near image boundaries, not an image quality issue.
